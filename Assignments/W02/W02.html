Case A
does not compile for cout << f — as a member, the overload's left operand is the Fraction, so it only matches f << cout. Need a non-member ostream& operator<<(ostream&, const Fraction&).
Case B
does not compile — f.num and f.den are private and the free function has no access. Fix: add friend ostream& operator<<(ostream&, const Fraction&); inside the class.
Case C
does not compile — line 6, assigning to const member PI in the body (also PI has no initializer). Fix: Circle(double radius) : PI(3.14159), r(radius) {}.
Case D
does not compile — Fraction(int) and Fraction(int, int = 1) are both viable for one int arg: ambiguous call. Fixes: delete Fraction(int n); OR collapse both into Fraction(int n = 0, int d = 1) : num(n), den(d) {}.
Case E
compiles, prints garbage — x = x; y = y; assigns the parameters to themselves; the members are never set. Fix: Point(int x, int y) : x(x), y(y) {} — in the init list x(x) unambiguously means member(parameter).
SAQ 1
the left operand of cout << obj is the stream, not your object; a member operator<< would take *this as the left operand (forcing obj << cout), and you cannot add members to std::ostream.
SAQ 2
cout << a << b << "\n"; needs each << to return the stream so the next can chain; with void it won't compile. Friendship: operator<< only reads state accessors would expose, is authored with the class, and adds no new mutation path.
SAQ 3
data is initialized before size (declaration order), so new int[size] uses an uninitialized size. Fix: declare/list size before data so the length is set first.
SAQ 4
(1) required for const/reference/no-default members and base-class construction; (2) avoids default-construct-then-assign, so it's one initialization instead of two.
