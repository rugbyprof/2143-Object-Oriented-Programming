part 1When Do Objects Die? — Q1, Q2

Q1: +A +B +C copy:B' visit -B' -B +D end -D -A

  1. C. It was made with new, and nothing ever calls delete. Heap objects don't care about scope. This is a leak.
  2. Destroying a raw pointer only destroys the pointer variable (an address). A raw pointer doesn't own what it points to. Compare unique_ptr in Part 7, which does.

Also worth discussing: B' is Visit's parameter, and it dies when Visit returns, before b leaves its block. D dies before A: locals die in reverse order of creation.

Rule of Three: destructor · copy constructor · copy assignment operator (any order).

part 3Writing Copy Assignment — Q5, Q6
  1. Version 1: a shallow copy. It leaks the old data_ and shares other's array, so there's a double free later. This is exactly what the compiler-generated version does.
  2. Version 2: breaks on self-assignment. When this == &other, delete[] data_ frees the very array it's about to copy from, then reads freed memory. (Also: if new throws, data_ is left dangling.)
  3. Version 3: a = b = c; fails (no viable overloaded '='). b = c returns void, so a = void makes no sense. Return IntStack& and *this, like the built-in types do.
IntStack& operator=(const IntStack& other) {
    if (this == &other) {
        return *this;
    }
    int* fresh = new int[other.capacity_];
    for (int i = 0; i < other.size_; ++i) {
        fresh[i] = other.data_[i];
    }
    delete[] data_;
    data_ = fresh;
    size_ = other.size_;
    capacity_ = other.capacity_;
    return *this;
}

Q6 grading: self-check, free the old array, deep copy, update all three members, return *this. Allocating before deleting (as shown) is a bonus: if new throws, the object is unchanged. Also accept delete-then-allocate with a self-check.

Enrichment, copy-and-swap: take the parameter by value, which reuses the copy constructor, swap the members, and let the parameter's destructor free the old data. That's self-assignment-safe and exception-safe in three lines.

part 4Move Semantics — Q7–Q9
IntStack(IntStack&& other) noexcept
    : data_(other.data_),
      size_(other.size_),
      capacity_(other.capacity_) {
    other.data_ = nullptr;
    other.size_ = 0;
    other.capacity_ = 0;
}
  1. Both objects point at one array. When the temporary dies it delete[]s it, leaving the new object dangling, and later there's a double free. (delete[] nullptr is safe, which is why we null it.)
  2. O(n): allocate and copy all n items. A move is O(1).
  3. Copying pointers and ints can't fail. A deep copy calls new, which can throw bad_alloc. (vector only moves elements while growing if the move is noexcept. Otherwise it copies, to stay safe.)

Q11: declaring a destructor (even an empty one) stops the compiler from generating the move operations, so every “move” quietly becomes a copy. It still works, but it's slower. Fix: delete the useless destructor (Rule of Zero), or write = default for all five.

class IntStack {
public:
    explicit IntStack(int capacity) {
        data_.reserve(capacity);
    }
    void Push(int value) {
        data_.push_back(value);
    }
    void Pop() {
        data_.pop_back();
    }
    int Top() const {
        return data_.back();
    }
    int Size() const {
        return static_cast<int>(data_.size());
    }
private:
    vector<int> data_;
};

Q12: vector<int> does it. Its own destructor, copy, and move are correct, and the compiler-generated versions for IntStack just call them. Tested: copy, then push to the copy, leaves the original's size unchanged, and a move works.

Accept capacity being ignored, or stored in a member to enforce a limit in Push.

Q21: Card is small, has no subclasses, and is cheap to copy, so storing it by value is simplest: no heap, no ownership questions, and the Rule of Zero. Character is polymorphic. A vector<Character> would slice every Wizard down to a plain Character (W06 Part 4), so the objects must live on the heap behind a base pointer. unique_ptr makes that heap object owned and freed automatically.

part 9Find the Error — Cases A–D
Case AReturns a reference to a local, which is destroyed when the function returns, so the reference dangles (clang warns: reference to stack memory associated with local variable 'message' returned). Fix: return string by value. Copy elision or a move makes it cheap.
Case Bpush_back may reallocate: the vector moves its elements to a bigger array and frees the old one. first still refers into the freed array (AddressSanitizer: heap-use-after-free). Fix: keep an index, re-read names[0] after inserting, or copy the string.
Case CTwo unique_ptrs each think they're the unique owner, so both delete the same int: a double free. Habit: never put a raw new in a smart pointer by hand. Use make_unique / make_shared, and transfer with std::move.
Case DUse after move. In practice it prints Welcome, with an empty name (tested), but the standard only promises a valid but unspecified string. Rule: after std::move(x), don't read x again until you give it a new value.
