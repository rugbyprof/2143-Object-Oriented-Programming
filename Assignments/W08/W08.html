part 1 When Do Objects Die? builds on W05 construction order

Every object has a lifetime: it starts when its constructor finishes and ends when its destructor runs. When the destructor runs depends on how the object was created:

Kind of objectCreated byDestroyed when…
Automatic (local)Tracer a("A");its enclosing { } block ends, in reverse order of creation
Parameter (by value)calling Visit(b)the function returns
Dynamic (heap)new Tracer("C")someone calls delete. If nobody does, never (a leak).

This class prints a line every time one of its objects is born, copied, or dies. A copy gets the original's name plus a '.

class Tracer {
public:
    Tracer(const string& name)
        : name_(name) {
        cout << "+" << name_ << " ";
    }
    Tracer(const Tracer& other)
        : name_(other.name_ + "'") {
        cout << "copy:" << name_ << " ";
    }
    ~Tracer() {
        cout << "-" << name_ << " ";
    }
private:
    string name_;
};

void Visit(Tracer t) {
    cout << "visit ";
}

int main() {
    Tracer a("A");
    {
        Tracer b("B");
        Tracer* c = new Tracer("C");
        Visit(b);
    }
    Tracer d("D");
    cout << "end ";
}

part 4 Move Semantics C++11

Sometimes the object you're copying is about to be thrown away, like a temporary returned from a function. A deep copy is wasted work: you build a new array, copy every element, and then the original deletes its array a moment later. Moving lets the new object steal the old object's resources instead.

ExpressionKindMeaning
a, names[0], *plvaluehas a name or address and will still be around. Must copy.
IntStack(5), MakeStack(), a + brvaluea temporary that's about to disappear. Safe to steal from.
std::move(a)rvalue“I promise I'm done with a. Treat it as a temporary.” It's only a cast. It moves nothing by itself.

A move constructor takes an rvalue reference, IntStack&&. It copies the pointer, then leaves the source empty but still safe to destroy:

IntStack(IntStack&& other) noexcept
    : data_(other.data_), size_(other.size_), capacity_(other.capacity_) {
    // ??? -- what must happen to other here?
}

part 5 The Rule of Five, and the Rule of Zero (continued)

Some things should never be copied: an open file, a network connection, a game window. Two copies would both try to close the same thing. Use = delete to forbid the operation. (= default asks for the compiler's version on purpose.)

class FileHandle {
public:
    explicit FileHandle(const char* path)
        : file_(fopen(path, "w")) {
    }
    ~FileHandle() {
        if (file_ != nullptr) {
            fclose(file_);
        }
    }
    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;
    bool IsOpen() const {
        return file_ != nullptr;
    }
private:
    FILE* file_;
};

part 6 RAII: Let the Destructor Clean Up

RAII (“Resource Acquisition Is Initialization”) is the most important C++ idiom: tie every resource to an object's lifetime. Acquire it in the constructor and release it in the destructor. Destructors of local objects always run when a scope ends, whether by reaching }, by return, or by an exception. So the resource is always released. FileHandle, vector, string, and unique_ptr are all RAII.

void Risky(bool fail) {
    int* scores = new int[100];
    Tracer guard("guard");
    if (fail) {
        throw runtime_error("boom");
    }
    delete[] scores;
    cout << "done ";
}

int main() {
    try {
        Risky(false);
        Risky(true);
        cout << "after ";
    } catch (const exception& e) {
        cout << "caught:" << e.what() << " ";
    }
}

part 8 Ownership Is a Design Decision applies to P01

A function's signature tells the caller who will own the object afterward. Good code makes ownership obvious from the types alone. The default is: hold by value, and borrow by reference. Reach for a pointer only when you need what a pointer adds.

Question 19what does the signature promise?
Match each signature to a meaning (A–F).
  • void Inspect(const Card& c)
  • void Discard(unique_ptr<Card> c)
  • void Track(shared_ptr<Card> c)
  • void MaybeShow(const Card* c)
  • unique_ptr<Card> Draw()
  • const Card& TopCard() const
A. Takes ownership. The caller gives it up.
B. Borrows, read-only, never null.
C. Gives ownership to the caller.
D. Becomes one of several owners.
E. Borrows, read-only, and it might be null.
F. Lets the caller look at something this object owns. Don't keep the reference longer than the object lives.

Takeawaythree rules

1. Every resource has exactly one clear owner, and that owner is an object whose destructor releases it. 2. Prefer the Rule of Zero: build classes out of members that already manage themselves. 3. A reference or raw pointer borrows. It must never outlive what it points to.
