array[3] Write the Code 5 pts · model answer 
class Manager : public Employee {
    int reports;
public:
    Manager(string n, double s, int r) : Employee(n, s), reports(r) {}

    void print() {
        Employee::print();
        cout << "Reports: " << reports << "\n";
    }
};

Manager m("Kim", 90000, 4); m.print(); prints Kim: $90000 then Reports: 4.

Grading notes

What counts

array[0]
1 pt for B M T, 1 pt for ~T ~M ~B (reverse order), 1 pt for the destructors appearing after the |. Destructors in constructor order (~B ~M ~T) loses the second point.
array[1]
1 pt per line (Y/N plus a reason that names the access level). The fix (1 pt) is protected. Also accept adding a protected (or public) setter/deposit method to Account and calling it in Line A. Making balance public or making Savings a friend earns 0, because the first breaks the stated rule and the second dodges the point of the question.
array[1] watch
“A fails because balance isn't inherited” is wrong. It is inherited but not accessible (W05 Q2). Deduct the reason point.
array[2] note
Without virtual this is technically hiding/redefinition; W05 calls it OVERRIDDEN, so accept either term. A student who points out the difference gets a nod; it's next week's topic (W06 Polymorphism).
array[3]
1 pt each: : public Employee; int reports private; Employee(n, s) in the initializer list; Employee::print() call; prints reports. Assigning name = n; salary = s; in the constructor body instead of chaining does not compile (Employee has no default constructor), so no chaining point. Forgetting Employee:: (so print() calls itself forever) loses the call point. Inheritance with no public keyword (private inheritance) loses the first point.
