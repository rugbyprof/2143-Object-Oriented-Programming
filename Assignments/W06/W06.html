part 3 virtual, override, and the Signature Rules builds on W05 overriding

A derived function only overrides a base function when the base version is virtual and the derived version matches it exactly: same name, same parameter types, same const. Get any of those wrong and you've written a brand-new function that just hides the base one, and the compiler won't complain.

Writing override after the derived function asks the compiler to check for you: “I mean to replace a virtual base method. Error if I didn't.” Also, once a function is virtual in the base class, it stays virtual in every derived class, whether or not the derived class repeats the word.

class Character {
public:
    virtual ~Character() {}
    virtual void attack();
    virtual void printName() const;
    virtual void heal(int amount);
    void rest();                        // NOT virtual
};

class Wizard : public Character {
public:
    void attack() override;             // (1)
    void printName() override;          // (2)
    void heal(double amount) override;  // (3)
    void rest() override;               // (4)
    void Attack() override;             // (5)
    void heal(int amount);              // (6)  no 'override' keyword
};

part 4 Pointers, References, and Slicing

Dynamic binding only happens through a pointer or a reference. If you copy a Wizard into a plain Character variable, only the Character part gets copied and the Wizard part is thrown away. This is called object slicing. Once an object is sliced, virtual can't bring the lost part back.

class Character {
protected:
    string name;
public:
    Character(string n) : name(n) {}
    virtual ~Character() {}
    virtual void printName() { cout << name << endl; }
};
class Wizard : public Character {
public:
    Wizard(string n) : Character(n) {}
    void printName() override { cout << "The magnificent " << name << endl; }
};
class Warrior : public Character {
public:
    Warrior(string n) : Character(n) {}
    void printName() override { cout << "The powerful " << name << endl; }
};

void byRef(Character& c) { c.printName(); }
void byPtr(Character* c) { c->printName(); }
void byVal(Character c)  { c.printName(); }

int main() {
    Wizard  merlin("Merlin");
    Warrior conan("Conan");

    byRef(merlin);                                  // (a)
    byPtr(&conan);                                  // (b)
    byVal(merlin);                                  // (c)

    vector<Character>  copies = {merlin, conan};
    copies[1].printName();                          // (d)

    vector<Character*> party  = {&merlin, &conan};
    party[1]->printName();                          // (e)
}

part 5 One Loop, Many Types the whole point

This is why polymorphism is worth the trouble: different kinds of objects go into one container, and one loop handles all of them without ever asking “what kind are you?” A derived class that doesn't override a virtual function just uses the version it inherited.

class Character {
protected:
    string name;
public:
    Character(string n) : name(n) {}
    virtual ~Character() {}
    virtual void printName() { cout << name << endl; }
    virtual void attack()    { cout << name << " swings wildly." << endl; }
};
class Warrior : public Character {                // overrides BOTH
public:
    Warrior(string n) : Character(n) {}
    void printName() override { cout << "The powerful " << name << endl; }
    void attack()    override { cout << name << " cleaves with an axe!" << endl; }
};
class Wizard : public Character {                 // overrides printName only
public:
    Wizard(string n) : Character(n) {}
    void printName() override { cout << "The magnificent " << name << endl; }
};
class Rogue : public Character {                  // overrides attack only
public:
    Rogue(string n) : Character(n) {}
    void attack() override { cout << name << " stabs from the shadows!" << endl; }
};

int main() {
    vector<unique_ptr<Character>> party;
    party.push_back(make_unique<Warrior>("Conan"));
    party.push_back(make_unique<Wizard>("Merlin"));
    party.push_back(make_unique<Rogue>("Vex"));
    party.push_back(make_unique<Character>("Bob"));

    for (auto& c : party) {
        c->printName();
        c->attack();
    }
}

part 6 Virtual Destructors builds on W05 destruction order

A destructor is looked up like any other member function. When you delete a derived object through a base pointer and the base destructor is not virtual, the compiler goes by the pointer's type and calls only the base destructor. The derived destructor never runs. (Officially the behavior is undefined. In practice, whatever the derived part owned leaks.)

class Base {
public:
    ~Base() { cout << "~Base "; }                 // not virtual
};

class Derived : public Base {
    int* data;
public:
    Derived() : data(new int[100]) {}
    ~Derived() { cout << "~Derived "; delete[] data; }
};

int main() {
    Base* p = new Derived();
    delete p;
}

part 7 Abstract Classes & Pure Virtual Functions

What does a plain Shape look like? What's its area? There's no good answer, because Shape is an idea and not a real thing. A pure virtual function (= 0, no body) says: “every derived class must provide this.” A class with at least one pure virtual function is abstract, so you can't create an object of it. You can still use pointers and references to it, and it can still have data, constructors, and ordinary methods. A derived class that overrides every pure virtual function is concrete. One that misses any is abstract too.

class Shape {
protected:
    string label;
public:
    Shape(string l) : label(l) {}
    virtual ~Shape() {}
    virtual double area() const = 0;              // pure virtual
    string name() const { return label; }         // ordinary method
};

class Circle : public Shape {
    double r;
public:
    Circle(double r) : Shape("circle"), r(r) {}
    double area() const override { return 3.14159 * r * r; }
};

class Blob : public Shape {
public:
    Blob() : Shape("blob") {}
    // no area()
};

part 9 Under the Hood: the vtable

How does c->attack() find the right function at run time? Every class that has virtual functions gets one hidden vtable, a table of function pointers with one slot per virtual function. Every object of that class carries a hidden vptr that points to its class's vtable. The vptr is set when the object is constructed. A virtual call follows the vptr, looks up the slot, and calls whatever it finds there.
