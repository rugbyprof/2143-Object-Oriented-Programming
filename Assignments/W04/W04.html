part 1 What Is a Constructor?

A constructor is a special member function that initializes an object when the object is created.

class Player {
    string name;
    int health;
public:
    Player() {
        name = "Unknown";
        health = 100;
    }
};

When we write Player p;, C++ automatically calls Player().

part 3 Overloaded Constructors

Just like normal functions, constructors can be overloaded — a class can have multiple constructors as long as their parameter lists differ.

class Player {
    string name;
    int health;
public:
    Player() { name = "Unknown"; health = 100; }
    Player(string n) { name = n; health = 100; }
    Player(string n, int h) { name = n; health = h; }
};

Now there are three ways to create a Player: Player a;   Player b("Bob");   Player c("Alice", 75);

part 4 Copy Constructor

Suppose we already have Player original("Bob", 80); and want a new object built from it: Player clone(original);. C++ uses a copy constructor:

Player(const Player& other) {
    name = other.name;
    health = other.health;
}

We're passing another Player object by const reference.

part 5 Why Copy Constructors Matter

For a class with plain members like string/int, the compiler-generated copy constructor is fine. But once a class holds a pointer…

class IntArray {
    int* data;
    int size;
};

…copying the pointer instead of what it points to gives two objects pointing at the same memory (a shallow copy):

Array A Array B data --------+ data --------+ | | +----> [10][20][30] <-------+

A custom copy constructor can allocate new memory instead — a deep copy:

Array A Array B data ----> [10][20][30] data ----> [10][20][30] separate memory separate memory

part 6 Constructor Initializer Lists

C++ provides a second syntax for constructors — the initializer list — which initializes members before the constructor body runs:

Body assignmentInitializer list
Player(string n, int h) {
    name = n;
    health = h;
}
 
Player(string n, int h)
    : name(n), health(h)
{
}

These often produce the same values, but they don't mean the same thing: construct members → enter body → assign new values vs. construct members using desired values → enter body. That distinction matters once members are themselves objects.

part 7 When Initializer Lists Are Required

Sometimes an initializer list isn't just prettier — it's required. Consider a const member:

class Student {
    const int id;
    string name;
};

This will not compile — id is supposed to already have a value by the time the body runs:

Student(int i, string n) {
    id = i;    // ERROR
    name = n;
}

Instead: Student(int i, string n) : id(i), name(n) {}. Initializer lists are especially important for const data members, reference members, member objects that need constructor arguments, and avoiding unnecessary default construction followed by assignment.

cheat sheet Constructors at a Glance
ConceptTypical syntaxPurpose
Default constructorPlayer()Create object without arguments
Overloaded constructorPlayer(string n)Create object using supplied values
Copy constructorPlayer(const Player& p)Create a new object from another object
Initializer listPlayer(...) : name(n), health(h)Initialize members directly, before the body runs

An initializer list is not a fourth kind of constructor — Player(), Player(string n), and Player(const Player& p) describe which constructor runs; : name(n), health(100) describes how that constructor initializes its members.
