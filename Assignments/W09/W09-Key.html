part 2Is It Really “Is-A”? — Q3, Q4

Q3: 20 16 (tested). Stretch reasonably assumed that setting the height doesn't change the width. A Square must break that assumption to stay square. So a Square can't stand in for a Rectangle, which violates LSP. Nothing crashes, so this bug is easy to miss. The fault is the hierarchy, not Stretch: “is-a” in code means behaves like, not “is a special case of, in math class.” Fix: don't derive one from the other. Make both derive from an abstract Shape with Area(), or make them immutable (no setters).

Q8: (1) Change behavior while running: the same Dealer object switches to Cautious after three losses, but an object can't change its own class. (2) Combine independent variations: 3 hit styles × 3 betting styles is 3 + 3 strategy classes, against 9 Dealer subclasses (and it multiplies with every new dimension). part 6Factory — Q9
  1. nullptr. The loop stores it, and the later member->Attack() dereferences null, so it crashes far from the real mistake (a bad save file). Better: throw invalid_argument("unknown kind: " + kind), so you fail loudly at the cause, or check the result and skip the line with a warning.
  2. Write the Bard class, and add one registry entry. The loading loop, the party, and the battle code don't change.

part 8Facade — Q12–Q14
string WarTable::Status() const {
    if (game_.isGameOver()) {
        return "Game Over: " + game_.winnerName();
    }
    string status = "Ready to play";
    if (last_.winner == 1) {
        status = game_.getPlayer1().getName()
                 + " wins the round!";
    } else if (last_.winner == 2) {
        status = game_.getPlayer2().getName()
                 + " wins the round!";
    }
    if (last_.wasWar) {
        status += " (WAR!)";
    }
    return status;
}

Q17 model sketch (accept any design with clear jobs and clear ownership):

Card value type: rank, suit; ToString() (Rule of Zero) Hand ◆ vector<Card> cards_; Add, Clear, Value(), IsSoft(), IsBust() Deck ◆ vector<Card> cards_; Shuffle(), Deal(); stacked ctor for tests HitStrategy abstract: ShouldHit(int) ──▷ Cautious, HouseRule, Reckless Blackjack ◆ Deck deck_; ◆ Hand player_, dealer_; ◆ unique_ptr<HitStrategy> dealerStyle_; Phase phase_; actions Deal/Hit/Stand (guarded by phase); const queries; NO cout/cin GameView abstract: virtual void run() = 0 ──▷ ConsoleView, TuiView ConsoleView ── Blackjack& game_ (association: borrows, doesn't own) main() ◆ Blackjack game; ◆ unique_ptr<GameView> view (chosen from argv); view->run()

Look for: no public data, no I/O in the game, a strategy (or at least a virtual) instead of the string chain, value or unique_ptr members instead of raw new, and Hand reused for both player and dealer.
