A template does not work for every type. It works for every type that supports the operations its body uses. Those operations are the template's requirements. They aren't written down anywhere (until Part 10). You find them by reading the code. 

template <typename T>
T Average(const vector<T>& values) {
    T total{};
    for (const T& value : values) {
        total += value;
    }
    return total / values.size();
}

part 3 Class Templates template_03 & 04

A class template is a recipe for classes. Box<int> and Box<string> are two separate classes made from one recipe. Everything you know about classes still applies: private data, constructors, const methods. In a real project the whole template lives in Box.h. Methods can be defined inside the class, or below it like this: 

template <typename T>
class Box {
public:
    explicit Box(const T& value);
    const T& Get() const;
    T Replace(const T& new_value);   // store new_value, return the OLD value
private:
    T value_;
};

part 5 A Generic Container template_06.cpp · builds on W01 stacks

Containers are where templates pay for themselves. A stack works the same way whatever it holds. In Worksheet 01 you wrote a stack of ints. Here it is once, for every type. Notice the design: Stack<T> has a vector<T> (composition) and only exposes stack operations. 

template <typename T>
class Stack {
public:
    void Push(const T& item) {
        items_.push_back(item);
    }
    T Pop() {
        if (items_.empty()) {
            throw underflow_error("Stack::Pop on empty stack");
        }
        T top = items_.back();
        items_.pop_back();
        return top;
    }
    const T& Peek() const {
        return items_.back();
    }
    size_t Size() const {
        return items_.size();
    }
private:
    vector<T> items_;
};

part 6 An Interface Without Inheritance template_07.cpp · compare W06 Part 7

In Worksheet 06, unrelated shapes shared an interface by inheriting from an abstract Shape. A template can do something similar without a base class: any type with the methods the template calls will fit. This is sometimes called duck typing: “if it has Name() and Score(), it's rankable.” 

template <typename T>
class Leaderboard {
public:
    explicit Leaderboard(size_t max_entries)
        : max_entries_(max_entries) {
    }
    void Submit(const T& entry) {
        entries_.push_back(entry);
        sort(entries_.begin(), entries_.end(), [](const T& left, const T& right) {
            return left.Score() > right.Score();
        });
        if (entries_.size() > max_entries_) {
            entries_.pop_back();
        }
    }
private:
    vector<T> entries_;
    size_t max_entries_;
};

part 7 Passing Behavior In template_08.cpp

A template parameter can stand for something you can call: a function, a lambda, or a function object (a class with operator()). This lets the caller decide part of the behavior. It's the Strategy pattern, chosen at compile time. The standard library does this everywhere: sort, map, set. 

template <typename T, typename Predicate>
vector<T> Filter(const vector<T>& items, Predicate keep) {
    vector<T> result;
    for (const T& item : items) {
        if (keep(item)) {
            result.push_back(item);
        }
    }
    return result;
}

bool IsEven(int value) {
    return value % 2 == 0;
}

class AtLeast {
public:
    explicit AtLeast(int threshold)
        : threshold_(threshold) {
    }
    bool operator()(int value) const {
        return value >= threshold_;
    }
private:
    int threshold_;
};

part 7 Passing Behavior In (continued)

A class template can take a behavior too. SortedList doesn't hard-code what “in order” means. The second template parameter is the ordering strategy, and it defaults to the standard library's less<T> (which uses <). 

template <typename T, typename Compare = less<T>>
class SortedList {
public:
    void Insert(const T& item) {                       // keeps items_ in order
        auto position = items_.begin();
        while (position != items_.end() && compare_(*position, item)) {
            ++position;
        }
        items_.insert(position, item);
    }
private:
    vector<T> items_;
    Compare compare_;
};

struct ByLength {
    bool operator()(const string& left, const string& right) const {
        return left.size() < right.size();
    }
};

part 8 Specialization template_09.cpp

A full specialization (template <>) replaces a template for one exact type. A partial specialization replaces it for a family of types, like every vector<T>. The compiler picks the most specialized match. 

template <typename T>                      // primary: anything that supports <<
class Formatter {
public:
    static string Format(const T& value) {
        ostringstream out;
        out << value;
        return out.str();
    }
};
template <>                                // full specialization: exactly bool
class Formatter<bool> {
public:
    static string Format(const bool& value) {
        return value ? "yes" : "no";
    }
};
template <>                                // full specialization: exactly string
class Formatter<string> {
public:
    static string Format(const string& value) {
        return "\"" + value + "\"";
    }
};
template <typename T>                      // partial specialization: any vector
class Formatter<vector<T>> {
public:
    static string Format(const vector<T>& values) {
        string result = "[";
        for (size_t i = 0; i < values.size(); ++i) {
            if (i > 0) {
                result += ", ";
            }
            result += Formatter<T>::Format(values[i]);
        }
        return result + "]";
    }
};
template <typename T>
void Show(const string& label, const T& value) {
    cout << label << " = " << Formatter<T>::Format(value) << "\n";
}

Function templates are different. You can fully specialize a function template, but you cannot partially specialize one. To give a function template special behavior for a family of types, you overload it instead. 

template <typename T>
T Total(const vector<T>& values) {          // (1) general version
    T sum{};
    for (const T& value : values) {
        sum += value;
    }
    return sum;
}

int Total(const vector<bool>& values) {      // (2) an overload, not a specialization
    int count = 0;
    for (bool value : values) {
        if (value) {
            ++count;
        }
    }
    return count;
}

part 9 Templates and Inheritance Together template_10 & 11 · builds on W06

Use inheritance when different types must be mixed together and chosen at run time. Use templates when the same code should work for many types. Strong designs use both: vector<unique_ptr<Character>> is a template holding a polymorphic hierarchy.

A base class can itself be a template. In the pattern below (called CRTP), each class passes itself to its base. Comparable<Coin> writes all the comparison operators in terms of one method, LessThan(). Counted<Coin> counts live objects with a static member. 

template <typename Derived>
class Comparable {
public:
    friend bool operator<(const Derived& left, const Derived& right) {
        return left.LessThan(right);
    }
    friend bool operator!=(const Derived& left, const Derived& right) {
        return left.LessThan(right) || right.LessThan(left);
    }
    // ... plus >, >=, <=, == written the same way
};

template <typename Derived>
class Counted {
public:
    Counted() {
        ++alive_;
    }
    Counted(const Counted&) {
        ++alive_;
    }
    ~Counted() {
        --alive_;
    }
    static int Alive() {
        return alive_;
    }
private:
    static inline int alive_ = 0;
};

class Coin : public Comparable<Coin>, public Counted<Coin> {
public:
    explicit Coin(int cents)
        : cents_(cents) {
    }
    bool LessThan(const Coin& other) const {
        return cents_ < other.cents_;
    }
private:
    int cents_;
};
class Gem : public Comparable<Gem>, public Counted<Gem> { /* similar, compares carats */ };

part 10 Concepts: Writing the Requirements Down template_12.cpp · C++20

In Part 6, Leaderboard's requirements were hidden in its code, and the error for Monster showed up deep inside the template. A concept turns the requirements into code the compiler checks where the template is used. It works a lot like an abstract base class's list of pure virtuals, but nothing has to inherit from anything. 

template <typename T>
concept Scorable = requires(const T& item) {
    { item.Name() } -> convertible_to<string>;
    { item.Score() } -> totally_ordered;     // supports < > <= >= == !=
};

template <Scorable T>
class Leaderboard { /* same as Part 6 */ };

cheat sheet Templates at a Glance
Concept Typical syntax Purpose
Function template template <typename T> T Larger(T a, T b) One algorithm for many types
Explicit argument Larger<double>(4, 9.2) Choose T yourself when deduction can't
Class template template <typename T> class Box One class design, many stored types
Out-of-class member template <typename T> const T& Box<T>::Get() const Define methods below the class, in the header
CTAD Box b{2.5}; Compiler deduces Box<double> from the constructor
Non-type parameter template <typename T, size_t N> A compile-time value that becomes part of the type
Default argument template <typename T = int> · Counter<> Use a type unless told otherwise
Function object bool operator()(int v) const Behavior with its own data, passed as a template argument
Full specialization template <> class Formatter<bool> Different code for one exact type
Partial specialization template <typename T> class Formatter<vector<T>> Different code for a family of types (classes only)
CRTP mixin class Coin : public Comparable<Coin> Reuse behavior across classes, no virtual
Concept template <Scorable T> State the requirements; errors appear at the use site
recap Static vs. Dynamic Polymorphism W06 meets W07
Templates (static) Virtual functions (dynamic)
Decided At compile time At run time
Shared base class? Not needed. The type just needs the right operations. Required
Mixed types in one container? No. A vector<T> holds one T. Yes, through unique_ptr<Base>
Interface written as A concept (or just the code, before C++20) An abstract base class
Cost More compiled code (one copy per type) A small lookup on each virtual call
Takeawayone question to ask

Does the behavior stay the same while the type changes? Use a template. Does the behavior change depending on which object you have at run time? Use a virtual function. Often a good design uses both.
