(e) and (f) are the traps. Characters compare by character code, and every uppercase letter comes before every lowercase one ('Z' is 90, 'a' is 97). Strings compare the same way, one character at a time, so "apple" > "Banana".

(c): the first argument says T is int and the second says double. Deduction needs one consistent T, and it won't convert to make them agree. Fixes: Larger(4.0, 9.2) or Larger(static_cast<double>(4), 9.2). Compiler message: no matching function for call to 'Larger'.

part 2What a Template Requires — Q3, Q4, Q5

Q3: default construction (T total{}), +=, division by a size_t (total / values.size()), and copying (returned by value).

  1. vector<double>{7, 8} — 7.5
  2. vector<int>{7, 8} — 7. It compiles, but 15 / 2 is integer division. A template does what the type does, even when that's not what you meant.
  3. vector<string>{"a", "b"} — ERROR: += works for strings, but there's no string / size_t. The error points inside Average at the return total / values.size(); line, followed by a “in instantiation of ... requested here” note pointing back at main().

Q5 model answer (a non-member, because Score() is public):

bool operator>(const Player& left, const Player& right) {
    return left.Score() > right.Score();
}

The template sets the rules (“T must support >”). Any class that follows them can use it. One template serves every type that fits, and nobody has to edit it to add a new type.

template <typename T>
Box<T>::Box(const T& value)
    : value_(value) {

const T& Box<T>::Get() const {
    return value_;

template <typename T>
T Box<T>::Replace(const T& new_value) {
    T old_value = value_;
    value_ = new_value;
    return old_value;

The two things every definition needs: repeat template <typename T> and name the class as Box<T>::. Don't repeat explicit outside the class. It only goes on the declaration.

  1. F. Different template arguments make different, unrelated types.
  2. F. The constructor is explicit, so there is no implicit int → Box<int> conversion.
  3. T. Class template argument deduction (CTAD, C++17).
  4. T. Member functions are only instantiated when used.
  5. F. They go in the header. A .cpp leads to linker errors (Case A).

The tie trap: Insert only moves past items that are strictly shorter. A new item goes in before existing items of the same length. So wizard lands before dragon, and orc lands before elf. Order among equal items depends on how the algorithm handles ties.

class Between {
public:
    Between(int low, int high)
        : low_(low), high_(high) {
    }
    bool operator()(int value) const {
        return value >= low_ && value <= high_;
    }
private:
    int low_;
    int high_;
};
// Filter(scores, Between(60, 90)) -> 72 88 63

Q19: a plain function has nowhere to store 60 and 90, because Filter calls it with only one argument. You'd need a separate function for every range, or globals. A function object carries its own state (data members set by the constructor). A capturing lambda, [low, high](int v) {...}, is the compiler writing this class for you.

  1. Q21.1 No. Compare is a template parameter, so different strategies make different types (they can't be assigned to each other).
  2. Q21.2 The default less<int>, which uses <, so the list is ascending.
  3. Q21.3 When the ordering must be chosen or changed at run time (the user clicks “sort by name” or “sort by score”), or when lists with different orderings must be the same type (stored together, passed to one function).

part 11Find the Error — Cases A–D, Q30
Case ALink error: Undefined symbols ... Box<int>::Box(int const&). When main.cpp is compiled it only sees declarations, so it expects Box<int>'s code to exist somewhere else. Box.cpp never uses Box<int>, so it never generates it. Fix: put the definitions in Box.h (or explicitly instantiate template class Box<int>; in Box.cpp, which is advanced).
Case BN. (1) Missing template <typename T> above the definition (unknown type name 'T'). (2) Box:: must be Box<T>:: (use of class template 'Box' requires template arguments).
Case CN. slots is read at run time, but a non-type template argument must be a compile-time constant. Redesign: take the capacity as a constructor argument, store it in a member, and use a vector<T> instead of array<T, N>.
Case DN (no viable constructor or deduction guide for deduction of template arguments of 'Stack'). CTAD only uses the constructor's arguments. Box b{2.5} passes a double to the constructor. Stack s; passes nothing, and the compiler won't look ahead to the Push(5) calls. Write Stack<int> s;.

Q30 (open-ended), examples of good answers: template: a Deck<T> / Pile<T> that shuffles and draws Cards (or tiles, or dice faces); a Stack<Move> for undo; a Leaderboard<Player>. Virtual: the UI screens, or the game variant (VideoPoker vs Blackjack), chosen at run time. Look for the reasoning: “same behavior, different type” → template. “different behavior picked at run time” → virtual.
