Case A
does not compile — a.num/a.den are private and this free function has no access. Fix: add friend Fraction operator+(const Fraction&, const Fraction&); inside the class.
Case B
does not compile — operator+ is missing const, so it can't be called on a, a const Fraction&. Fix: Fraction operator+(const Fraction& rhs) const { ... }.
Case C
compiles, wrong answer — comparing raw num/den fails for unreduced-but-equal fractions (1/2 vs 2/4). Fix: cross-multiply — return num * rhs.den == rhs.num * den;.
Case D
does not compile (line 13) — a + 2 resolves via the member Fraction::operator+ found on a's type, implicitly converting 2 to Fraction for the parameter. 2 + a looks for a member operator+ on int, which doesn't exist, and there's no non-member operator+(int, const Fraction&) to fall back on. Fix: add a non-member/friend operator+ so both orders resolve.
Case E
compiles, undefined behavior — the default copy constructor copies the data pointer's address, not the array. b1 and b2 both point at the same heap block; when both destruct (implicitly, no destructor here yet) or when either is used after the other frees, you get a double free / dangling pointer.
SAQ 1
without const, operator+ isn't callable on a const Fraction or a const Fraction& parameter — e.g. void f(const Fraction& a, const Fraction& b) { a + b; } fails to compile.
SAQ 2
cout << obj's left operand is an ostream — you can't add members to it, so the overload must be free. a + b's left operand is your own Fraction, which you're free to add a member to, so a member overload is natural (and lets operator+ reach private data without friend).
SAQ 3
both Buffers end up owning (pointing at) the same heap array; whichever is destroyed/frees first leaves the other with a dangling pointer, and freeing twice is undefined behavior. Term: shallow copy.
SAQ 4
Fraction's members are plain value types (int) with no ownership semantics, so a member-wise copy is a complete, independent copy. A raw owning pointer (like Buffer::data) would force a hand-written copy constructor, destructor, and operator= — the “Rule of Three.”
